# EasyEQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build EasyEQ (简易均衡器), a free, open-source, native macOS window app that applies a 10/15/31-band graphic EQ to all system audio, with presets and a Chinese/English UI.

**Architecture:** A Swift Package with three targets. `EasyEQCore` holds all pure, unit-tested logic (band layouts, biquad math, curve conversion, presets, editing session, settings, localization). `EasyEQAudio` holds the real-time EQ processor (offline-tested) and the Core Audio process-tap engine (manually verified). `EasyEQ` is the SwiftUI executable. A shell script assembles the executable and resources into an ad-hoc-signed `EasyEQ.app`.

**Tech Stack:** Swift 6.2 toolchain (Xcode 26.3), SwiftUI, Core Audio Process Tap API (`CATapDescription`, `AudioHardwareCreateProcessTap`), Swift Testing (`import Testing`), SwiftPM, bash, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-21-easyeq-design.md` (Chinese). Section numbers below (§) refer to it.

## Review Focus

1. **Hand-edited or corrupt preset files** (invalid JSON, wrong band count for its layout, NaN/±inf, gains outside ±12): the app must skip unreadable files and clamp/repair readable ones, never crash or show a broken preset. → Task 3 tests.
2. **Output devices at 44.1 kHz or 96 kHz**, including the 20 kHz band of the 31-band layout at 44.1 kHz (above Nyquist/2 region): filters must stay stable (no NaN, no runaway), and coefficients must be recomputed when the sample rate changes. → Task 6 tests.
3. **Every band at +12 dB:** output must not clip (auto preamp + limiter keep |sample| ≤ 1.0). → Task 2 and Task 6 tests.
4. **Fast slider dragging / preset switching while audio plays:** no clicks — gain changes are smoothed. → Task 6 test.
5. **Deleting or renaming the selected preset, duplicate or blank names:** deleting the selected user preset falls back to built-in Voice; blank names are rejected; duplicates get a numeric suffix. → Task 4 tests.

### Task 2: Biquad math, EQ settings, curve conversion, auto preamp

**Files:**
- Create: `Sources/EasyEQCore/Biquad.swift`, `Sources/EasyEQCore/EQSettings.swift`, `Tests/EasyEQCoreTests/EQSettingsTests.swift`

**Interfaces:**
- Consumes: `BandLayout` (Task 1).
- Produces:
  - `public struct BiquadCoefficients: Equatable, Sendable { public var b0, b1, b2, a1, a2: Double }` (normalized, a0 = 1)
  - `public static func peaking(frequency: Double, gainDB: Double, q: Double, sampleRate: Double) -> BiquadCoefficients` — RBJ Audio EQ Cookbook peaking EQ. If `frequency >= 0.49 * sampleRate`, clamp frequency to `0.49 * sampleRate` (keeps 20 kHz stable at 44.1 kHz). gainDB == 0 → identity (b0=1, others 0).
  - `public func magnitudeDB(at hz: Double, sampleRate: Double) -> Double`
  - `public struct EQSettings: Codable, Equatable, Sendable { public var layout: BandLayout; public var gains: [Double]; public init(layout: BandLayout, gains: [Double]) }`
  - `public static func flat(_ layout: BandLayout) -> EQSettings`
  - `public func responseDB(at hz: Double, sampleRate: Double = 48_000) -> Double` — sum of each band's `magnitudeDB`.
  - `public func converted(to layout: BandLayout) -> EQSettings` — linear interpolation of gains over log2(frequency); target frequencies outside the source range take the nearest end value; result rounded to 0.1 dB and clamped.
  - `public func autoPreampDB(sampleRate: Double = 48_000) -> Double` — `-max(0, max responseDB over 200 log-spaced points from 20 Hz to 20 kHz)`.

  - `public init(selection: PresetRef, saved: EQSettings)`

### Task 7: System audio engine (process tap)

**Files:**
- Create: `Sources/EasyEQAudio/SystemAudioEngine.swift`

**Interfaces:**
- Consumes: `EQProcessor` (Task 6).
- Produces:
  - `public enum EngineState: Equatable, Sendable { case stopped, running(deviceName: String), permissionDenied, failed(String) }`
  - `@MainActor public final class SystemAudioEngine: ObservableObject { @Published public private(set) var state: EngineState; public let processor: EQProcessor; public init(); public func start(); public func stop() }`

Approach (this task is verified manually; no unit test can reach Core Audio hardware):
1. `CATapDescription(stereoGlobalTapButExcludeProcesses: [ownProcessObjectID])`, `muteBehavior = .mutedWhenTapped`, `isPrivate = true`; `AudioHardwareCreateProcessTap`. Own process object ID via `kAudioHardwarePropertyTranslatePIDToProcessObject`.
2. Read the default output device (`kAudioHardwarePropertyDefaultOutputDevice`), its UID, name and nominal sample rate.
3. Create a private aggregate device (`AudioHardwareCreateAggregateDevice`) whose main sub-device is that output device and whose tap list contains the tap UUID (`kAudioAggregateDeviceTapListKey`, `kAudioAggregateDeviceTapAutoStartKey = true`).
4. `AudioDeviceCreateIOProcIDWithBlock` on the aggregate: copy tap input buffers to output buffers, `processor.process(...)` on the output in place. `processor.setSampleRate` from the device rate.
5. Listen to `kAudioHardwarePropertyDefaultOutputDevice` and the device's `kAudioDevicePropertyNominalSampleRate`; on change, tear down and rebuild (steps 2–4) on the main actor.
6. `stop()` destroys IOProc, aggregate device and tap (`AudioHardwareDestroyProcessTap`) so the system audio un-mutes. Call it from `applicationWillTerminate`.
7. Permission: if tap creation returns an error, or the tap delivers only exact zeros for 3 s while the output device reports it is running, set `.permissionDenied`. Re-check whenever the app becomes active.
- Add the bundle key `NSAudioCaptureUsageDescription` (Task 10 Info.plist) — the tap prompt depends on it.
